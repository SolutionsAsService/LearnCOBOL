01What this is

COBOL — Common Business-Oriented Language — was designed by the CODASYL committee and first specified in 1960; the current standard is ISO/IEC 1989. It was written to read like English business prose rather than like mathematics.

The programs here are small and self-contained: payroll, loans, inventory, tax, stock valuation, aquaculture, crop rotation. They run from 27–87 lines each and do one job apiece — the kind of work the language was written for.

02The card

COBOL's fixed source format is a punch card turned into a rule. The column a character sits in decides whether the compiler reads it at all.

1 8 12 24 36 48 60 72 80

  • 1–6 Sequence

    Optional line numbers. The compiler ignores them; they existed so a dropped deck of cards could be sorted back into order.

  • 7 Indicator

    * in this column makes the whole line a comment. - continues a literal from the line above.

  • 8–11 Area A

    Division, section and paragraph headers, and 01-level records, must begin here.

  • 12–72 Area B

    Everything else — statements, clauses, subordinate data items. This is where the program lives.

Columns 73 to 80 are not code. In fixed format the compiler never reads them, which is why a line can look complete and still be truncated. In this repository 26 of 32 files contain 48 such lines; wherever one appears in a listing on this page, its tail is struck through. One is shown outright, below.

The instrument is 1960; these files are not. Across the 1,707 non-blank lines in the corpus, 700 begin at column 5, 578 at column 1, and only 241 begin anywhere in Area A (columns 8–11) — just 22 of them exactly at column 8, where division headers are supposed to start. This code is indented the way modern code is indented, and GnuCOBOL compiles it either way. The rule above is what the language still carries; the measurement is what these programs actually do.

    03The four divisions

    Every COBOL program is these four, in this order. Nothing else is allowed at the top level.

    • Identification

      Names the program. PROGRAM-ID is the only clause that is always required.

    • Environment

      Declares the machine: which files map to which external names, via SELECT … ASSIGN.

    • Data

      Declares every field before it is used, with a picture: PIC 9(5)V99 is five digits, an implied decimal point, two more digits.

    • Procedure

      The executable part: named paragraphs, performed in sequence or in loops. No anonymous blocks, no nesting by indentation alone.

    04The programs

    All 32, as they are in the repository. Open a program to read ten lines from its PROCEDURE DIVISION; follow the filename to the full source. FD/SELECT counts the files a program opens — 0 means it is console-driven and talks to the terminal with ACCEPT and DISPLAY instead.

      05Run one

      These are fixed-format sources, so GnuCOBOL compiles them as they stand.

      # compile to a standalone executable
cobc -x PayrollProcessing.cbl
./PayrollProcessing

# or build a module and run it through cobcrun
cobc -m PayrollProcessing.cbl
cobcrun PayrollProcessing

# free-format sources, if you write your own
cobc -x -free MyProgram.cbl

      cobc is the GnuCOBOL compiler. -x produces an executable, -m a loadable module, and -free switches off the 80-column rules described above — which is the fastest way to see what the card was doing for you.
